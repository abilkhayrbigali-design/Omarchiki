# Архитектура AuditGym

Что строим — в [REQUIREMENTS.md](REQUIREMENTS.md). Бухгалтерская модель и типы ошибок — в [DOMAIN.md](DOMAIN.md). Здесь — как это устроено в коде и почему.

## 1. Принципы

| № | Принцип | Что это даёт |
|---|---|---|
| P1 | **Чистое детерминированное ядро.** Никаких часов, глобальной случайности, `float` для денег, сети и файлов внутри ядра | K4: побайтовая воспроизводимость |
| P2 | **Эталон по построению плюс независимая проверка.** Генератор знает ошибки, потому что сам их внёс. Отдельный решатель находит их заново только по открытым данным. Результаты обязаны совпасть | K2: согласованные и разрешимые данные |
| P3 | **Разделение полномочий.** Код, собирающий наблюдения, физически не имеет ссылки на эталон | K1: нет утечек |
| P4 | **Смысл отдельно от представления.** Внутри — стабильные внутренние ключи. Публичные ID и порядок строк назначаются последним шагом от своего потока случайности | K4: перестановка и смена ID ничего не меняют |
| P5 | **Общая награда строго по кейсу.** Эксперименты считаются рядом и показываются отдельно | K3 |
| P6 | **Закрытый отказ.** Любой сбой превращается в код ошибки из фиксированного списка, без traceback и путей | K1 |

## 2. Стек

| Что | Выбор | Почему |
|---|---|---|
| Язык | Python 3.11 | версия официальной проверки |
| Зависимости в рантайме | только стандартная библиотека | проверка без сети; нечему сломаться; образ маленький |
| Деньги | `int` в минимальных единицах | требование кейса; нет ошибок округления |
| Курсы и арифметика | `decimal.Decimal` из строк | точная и воспроизводимая арифметика |
| Время | `datetime` с фиксированными смещениями | без зависимости от tzdata |
| Случайность | свои именованные потоки от SHA-256 | см. раздел 7 |
| Окружение разработки | `uv`, `uv.lock` | зафиксированные версии |
| Тесты | `pytest`, `hypothesis` | проверка свойств на случайных входах |
| Стиль | `ruff` | один инструмент для линта и формата |
| Контейнер | `Dockerfile` на `python:3.11-slim` с фиксированным digest, запуск с `--network none` | условия проверки |
| Единая команда | `make check` → `python -m auditgym check` | работает и без установленных dev-зависимостей |

Gymnasium как зависимость не подключаем: кейс требует контракт в его стиле, а не наследование.

## 3. Конвейер генерации

```
seed + config ──► именованные потоки случайности
                        │
  1. world     скрытая история: компания, клиенты, счета, платежи, отвлекающие случаи
  2. books     чистые проводки по политике ──► проверка инвариантов I1–I7
  3. inject    ошибки: изменение + запись эталона + запись в provenance
  4. present   публичные ID и порядок строк (отдельный поток)
  5. bundle    открытое: manifest, ledger, invoices, payments, fx, policy
               закрытое: truth, provenance
  6. verify    независимый решатель по открытому == эталон
                        │
                        ▼
        процесс-оценщик: хранилище(открытое) + grader(закрытое)
                        ▲
                        │  JSON-строки: reset / step
                        ▼
        клиент ◄── harness ◄── policy.act(observation)
                      └──► trajectories.jsonl (ровно то, что видела политика)
```

**Самопроверка с детерминированной перегенерацией.** Если на шаге 6 решатель и эталон расходятся, генератор повторяет попытку с тем же seed и следующим номером попытки. Номер попытки пишется в provenance. Цель — ноль повторов на любом seed: каждый повтор считается ошибкой генератора и попадает в отчёт. Но на скрытом seed жюри среда всё равно выдаст согласованный эпизод.

## 4. Модули

```
src/auditgym/
  contracts/   типы данных, коды ошибок, схема и проверка config, версии
  util/        money, timeutil, rng, canon (канонический JSON и CSV)
  world/       модель мира, построение истории, отвлекающие случаи
  books/       политика, правила проводок, инварианты
  inject/      четыре инжектора и два сценария взаимодействия
  present/     публичные ID, порядок, преобразование готового эпизода
  episode/     bundle, чтение и запись на диск, оркестратор generate
  verify/      независимый решатель и проверка достаточности доказательств
  grading/     нормализация, matcher, награда
  env/         хранилище, действия, калькулятор, наблюдения, сессия эпизода
  server/      протокол и сервер на stdio
  client.py    RemoteEnv: reset/step поверх протокола
  policies/    random_explorer, reconcile, flag_all, oracle, пробы на трюки
  harness/     запуск политик, траектории, отчёт, check
  cli.py
schemas/       JSON Schema всех форматов
configs/       версионированные конфигурации: train.v1, dev.v1, smoke.v1
episodes/      train/, dev/ — открытые файлы; private/ — их эталон
trajectories/  trajectories.jsonl
tests/         unit/, contract/, data/, reward/, repro/, leak/
```

**Границы импорта** проверяются тестом, который разбирает импорты через `ast`:
- `env/observe.py`, `client.py` и политики, кроме `oracle`, не импортируют `grading`, `inject`, `world`, `verify` и закрытую часть `episode`.
- `verify/` не импортирует `inject/` и `world/`. Он читает только открытый bundle.
- `grading/` зависит только от `contracts/` и `util/`.

## 5. Среда

```python
env = auditgym.make(mode="open")
obs, info = env.reset(seed=123, config=cfg)
obs, reward, terminated, truncated, info = env.step(
    {"action": "list_records", "args": {"table": "ledger", "cursor": None, "limit": 50}}
)
```

**Наблюдение:** `{"result": ..., "error": null | {"code", "message"}, "steps_remaining": n}`. Первое: `{"task", "manifest", "policy", "steps_remaining"}`.

**Действия**

| Действие | Поведение |
|---|---|
| `list_records(table, cursor, limit)` | Таблицы `ledger`, `invoices`, `payments`, `fx`. До 50 строк и `next_cursor`. Для документов возвращается краткая запись без `line_items` |
| `get_record(table, id)` | Одна запись по ID |
| `get_document(doc_id)` | Полный документ, включая `line_items` |
| `calculator(expression)` | Точная десятичная арифметика: `+`, `-`, `*`, `/`, скобки, унарный минус. Свой разборщик, без `eval`. Лимиты на длину выражения и число цифр |
| `submit(findings)` | Проверка структуры → сопоставление → награда → `terminated=true` |

Полные документы даются только по одному, поэтому прочитать все 200 документов за 100 шагов нельзя. Агенту приходится отбирать кандидатов по краткому списку — это и есть расследование.

**Коды ошибок:** `unknown_action`, `invalid_arguments`, `unknown_table`, `unknown_id`, `invalid_cursor`, `limit_out_of_range`, `calculator_error`, `episode_finished`, `internal_error`. Сообщение — фиксированный текст для каждого кода. Любая ошибка расходует шаг.

**Завершение**
- `submit` → `terminated=true`. Неверная структура → награда −1, причина в журнале оценщика.
- Шаги кончились → `truncated=true`, ответ считается пустым.
- Лимит времени отслеживают сервер и harness; ядро по умолчанию не смотрит на часы. Для запуска в одном процессе лимит включается явно: `AuditEnv(time_limit_s=60)`.
- Действие после завершения → `episode_finished`, награда 0.

**Режимы**
- `open`: терминальная награда возвращается политике.
- `closed`: политике уходит `reward=0.0` и `info.reward_withheld=true`. Настоящая награда и разбор пишутся в журнал оценщика, путь к которому знает только процесс-оценщик.

## 6. Сопоставление и награда

1. **Нормализация.** Тип — точное значение из перечня. `affected_ids` и `evidence_ids` — множества. Сумма — целое. Валюта — код в верхнем регистре.
2. **Совместимость пары** вывод–ошибка: тип равен; множества `affected_ids` равны; `|claimed − expected| ≤ допуск`; валюта равна; `evidence_ids` содержат целиком хотя бы один допустимый набор.
3. **Паросочетание.** Максимальное паросочетание в двудольном графе совместимости. Число TP не зависит от порядка выводов и от строк ID.
4. **Метрики** и краевые случаи — строго по S07. **Награда** — строго по S08.

`explanation` на награду не влияет.

**Экспериментальная награда** считается отдельно и общую не заменяет. В ней вывод засчитывается, только если все его доказательства агент действительно запрашивал в этом эпизоде. Это закрывает угадывание ID. В общую формулу это не включено, потому что oracle организаторов отправляет ответ без исследования и должен получать максимум.

## 7. Детерминизм

- **Именованные потоки.** `seed_потока = SHA-256(seed, config_hash, версия, имя, попытка)`. У мира, каждого инжектора и представления свой поток: изменение одного не сдвигает остальные.
- **Запрещено в `src/`:** `random` на уровне модуля, `time`, `datetime.now`, `uuid4`, `os.urandom`, встроенный `hash()`, обход `set` и `dict` без сортировки там, где порядок попадает в вывод.
- **Канонический вывод.** JSON с сортировкой ключей, фиксированные разделители, UTF-8, `\n`. CSV с фиксированным порядком столбцов.
- **Отпечаток эпизода** — SHA-256 по каноническим файлам. Тест генерирует эпизод дважды в отдельных процессах с разным `PYTHONHASHSEED` и сравнивает отпечатки.
- **Никаких развязок по ID** в семантике, решателе и matcher.

## 8. Изоляция

| Слой | Мера |
|---|---|
| Процессы | Эталон живёт только в процессе-оценщике. Политика получает канал JSON-строк и больше ничего |
| Объекты | Наблюдение проходит сериализацию: изменить состояние среды через возвращённый объект нельзя. Записи неизменяемы |
| Код | Модуль наблюдений не импортирует эталон, см. границы импорта |
| Идентификаторы | `episode_id` и публичные ID — ключевой хеш, не содержат seed и номеров по порядку генерации |
| Ошибки | Только фиксированные коды и тексты |
| Файлы | В закрытом режиме эталон на диск не пишется. Эталон открытых эпизодов лежит отдельно в `episodes/private/` |
| Контейнер | Запуск с `--network none`, политика без прав на каталог оценщика |

**Тест слепой замены.** Тот же эпизод запускается с подменённым эталоном, и все наблюдения до `submit` обязаны совпасть побайтово. Это доказывает, что наблюдения от эталона не зависят.

## 9. Тесты

| Набор | Что проверяет | Критерий |
|---|---|---|
| `tests/contract` | формы `reset/step`, схемы, страница 50, 100 шагов, завершение, все виды неверного ввода | K1 |
| `tests/leak` | слепая замена; поиск seed, путей и полей эталона в наблюдениях, `info`, ошибках и траекториях; границы импорта | K1 |
| `tests/data` | инварианты чистых книг; объявленное расхождение после ошибки; решатель == эталон; достаточность каждого набора доказательств | K2 |
| `tests/reward` | свойства S10, атаки S11, краевые случаи метрик | K3 |
| `tests/repro` | повтор seed и действий; перестановка и смена ID сохраняют ответ oracle и награду; разные `PYTHONHASHSEED` | K4 |
| `tests/unit` | деньги, время, калькулятор, потоки случайности, канонический вывод | — |

**Прогон по объёму.** `python -m auditgym sweep` перебирает тысячи пар seed × случайный допустимый config и считает: нарушения инвариантов, расхождения решателя с эталоном, повторы генерации, время. Цель по всем счётчикам — ноль.

**Пробы на трюки.** Набор примитивных политик: пометить всё; самые крупные суммы; последние строки; круглые суммы; одинаковая сумма у одного клиента. У каждой F1 должен быть низким. Таблица результатов идёт в записку как измеренный разбор сбоев.

## 10. Бюджеты

Генерация эпизода максимального размера — до 2 секунд. Один шаг — до 50 мс. Память — до 200 МБ. Лимит проверки: 60 секунд на эпизод, 2 ядра, 4 ГБ.
