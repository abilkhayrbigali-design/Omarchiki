# AuditGym — правила для агентов

Genesis Hackathon, трек FinTech: «RL-среды для дообучения моделей финансового аудита».
Этот файл — источник правды для всех агентов: Claude Code, Codex, субагентов.

## Что мы строим

Воспроизводимую RL-среду для ИИ-аудитора: генератор вымышленных компаний со скрытыми бухгалтерскими ошибками, среду `reset/step` с пятью инструментами, сопоставление выводов с эталоном и награду.

Жюри оценивает **корректность среды и оценщика**, а не награду нашего агента. UI и обучение весов баллов не дают — их не делаем.

## Стек

Python 3.11. В рантайме только стандартная библиотека. Для разработки: `uv`, `pytest`, `hypothesis`, `ruff`. Контейнер на `python:3.11-slim`.

## Команды

| Команда | Что делает |
|---|---|
| `uv sync` | окружение разработки на Python 3.11 |
| `make test` / `make test-fast` | все тесты / без медленных |
| `make check` | единая команда проверки: тесты, прогон генератора, имитатор жюри |
| `make docker-check` | то же в контейнере без сети, 2 CPU, 4 ГБ |
| `python -m auditgym generate --seed N --config configs/train.v1.json --out runs/ep` | сгенерировать эпизод на диск |
| `python -m auditgym run --policy reconcile --seed N` | прогнать политику и записать траекторию |
| `python -m auditgym sweep --config configs/dev.v1.json --seeds 1000` | прогон генератора по объёму с независимой проверкой |
| `python -m auditgym baselines --config configs/dev.v1.json --seeds 300` | четыре политики на многих эпизодах |
| `python -m auditgym jury` | имитатор закрытой проверки жюри |
| `python -m auditgym judge-check` | опубликованные определения проверок через `judge_adapter.py` |
| `python -m auditgym export` | открытые эпизоды и траектории |

Числа в README и записке обновляются только из прогонов, сохранённых в `reports/`.

## Жёсткие правила

1. **Деньги — только `int`** в минимальных единицах. Курсы — `Decimal` из строк. `float` в `src/` допустим только для итоговой награды и метрик.
2. **Случайность только через `auditgym.util.rng`.** Запрещены `random` на уровне модуля, `time`, `datetime.now`, `uuid4`, `os.urandom`, встроенный `hash()`. Исключение: `harness/` измеряет время прогона для диагностики и тайм-аута.
3. **Порядок.** Не обходить `set` и `dict` без сортировки там, где порядок попадает в вывод. Никаких развязок по строке ID или по позиции записи. Единственное исключение — опубликованное жюри правило выбора пар в matcher (`issue_id`, индекс вывода): оно не меняет TP, FP, FN и награду.
4. **Утечки.** Код наблюдений не импортирует эталон. В наблюдениях, `info`, ошибках и траекториях нет seed, путей, traceback и полей эталона. Ошибки — только коды из фиксированного списка.
5. **Безопасность.** Никаких `eval`, `exec`, сети, записи вне `runs/`. Калькулятор — свой разборщик.
6. **Общую награду и matcher из кейса не менять.** Эксперименты считаются рядом и показываются отдельно.
7. **Независимость решателя.** Тот, кто пишет `verify/`, не читает `inject/` и `world/`.
8. **Контракты** в `src/auditgym/contracts/` и `schemas/` меняет только интегратор.
9. **Данные только вымышленные.** Никаких реальных компаний, людей, счетов.
10. **Честность.** Любое число в README и записке берётся из сохранённого прогона в `runs/`. Не заявлять улучшений модели. Ограничения записывать, а не прятать.

## Параллельная работа

- Один пакет — одна ветка `wp/<номер>-<имя>` в своём worktree. Каталоги пакетов не пересекаются, владельцы указаны в [docs/PLAN.md](docs/PLAN.md).
- Нужна правка в чужом каталоге или в контрактах — сообщи интегратору, сам не трогай.
- Агент коммитит только в свою ветку. В `main` сливает интегратор.
- `git push`, публикация репозитория, регистрации и всё платное — только с явного согласия человека.
- Ответы организаторов на вопросы из раздела 7 [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) сначала вносятся в документы, потом в код.

## Готово — это когда

- Требование из [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) закрыто тестом, в имени теста его код.
- `make test` и `make check` проходят.
- Новая случайность идёт через свой именованный поток, отпечаток эпизода стабилен.
- В отчёте агента сказано, что сделано, что не сделано и что не проверено.
